# Architecture and implementation specification

## Objective
Minimize time and compute to a genuinely qualified candidate, with zero accepted correctness regressions. First-attempt success is a metric, not a promise. Separate reusable core, tool adapters and TRIPWIRE profile. Python 3.11+, standard library first, SQLite for durable transactions; use subprocess argument arrays, not shell strings. No new service, API key, GPU or vector database required for MVP. Use local Codex CLI if supported; check installed help and authentication, do not assume API access or nested agent support.

## Components and contracts
1. Inventory: record git revision, hashes of all physical inputs, tool/PDK/container versions, resolved config, SDC, corner set, seed, threads, environment and stage artifacts. Distinguish missing from zero. Hash report files and include path/line evidence in every observation. Detect incompatible baselines. Reuse `scripts/ci/status_merge_screen.py`, `functional_setup_frontier.py`, `audit_promotion_inputs.py`, `verify_integrated_candidate.py` read-only; avoid duplicating their checks.
2. Diagnostics: parse actual OpenSTA reports and flow metrics; schema includes stage, corner, check, start/end pin, ordered pin/net/arc transitions, slack, arrival, required, slew, cap, fanout, cell and net incremental delays, clock latency/uncertainty when available. Keep original units, normalize ns explicitly. Handle rise/fall and setup/hold separately, deduplicate endpoints for TNS only when complete. Compare matching paths by stage/corner/check/ordered pins; mark changed paths, ambiguous matches and missing fields. Cluster by shared launch, shared upstream cone/net, endpoint domain and physical proximity; rank coverage and delay contribution. Retrieve ODB/DEF geometry and SPEF with pinned tools when present; never guess wire delay from cell count. Map synthesis names to RTL using actual netlist and provenance, report uncertainty. Report electrical, overflow, antenna, DRC/LVS, utilization, buffer/diode growth and macro constraints separately. Do not confuse functional restricted frontier with whole-design timing.
3. Knowledge retrieval: manifest of public sources, exact revision, URL, license, hash and local path. Index docs and source via ripgrep or SQLite FTS5; return excerpts with file/line and version. Curated recipes for setup/hold, congestion, antenna/electrical, clocking, SRAM/macro, equivalence, synthesis mapping. Treat retrieved text as data, never commands. Record unsupported commands and verified local help. Optional semantic index only if measured useful.
4. Planner: diagnosis agent emits evidence IDs, ranked causal hypotheses, falsifiers and unknowns; proposal agents independently generate RTL, physical and alternative design hypotheses; skeptical reviewer checks equivalence, physical plausibility, duplication and cost before dispatch. Use strict JSON schema; validate output, reject malformed or unsupported evidence. Separate context per role; no broad shell in read-only agents. Use Codex CLI noninteractive only after capability check and user-approved resource configuration; capture transcript and exit status. If unavailable, support manual proposal JSON without pretending autonomy.
5. Controller: durable SQLite campaign ledger, immutable experiment IDs, unique input/config/seed/stage fingerprints, transactionally reserve resource budgets before dispatch; mark queued/running/completed/failed/abandoned; recover interrupted jobs and do not double-launch. Each proposal includes family, mechanism, expected effect, falsifier, baseline, patch hash, checks, cost, stage and rollback. Enforce two failed attempts per mechanism -> re-diagnose; three failures per family -> block it until independently reviewed new evidence and explicit reset; no duplicate fingerprints; full-flow budget; wall time, CPU, disk and concurrency caps. Never treat timeout or missing output as a pass. Use process groups, timeout termination, bounded logs and scratch isolation. Controller must mediate all runs; command allowlist configured by user, no arbitrary agent shell or remote actions. Default one worker, two full local flows per campaign, 12h elapsed budget, explicit opt-in for expensive jobs. Do not launch indefinitely. Capture agent invocations in budget too. Distinguish wall-time from aggregate compute. Start dry-run.
6. Experiment execution: materialize independent source copies; verify base hashes before/after; one physical change per experiment per repo rules. Stage ladder: static/functional/formal -> native mapped synthesis -> placement and CTS -> global routing and post-repair all-corner STA -> detailed route/extracted STA -> unchanged official qualification (user only). Existing candidate rules override generic ladder. Checkpoint keys include all upstream dependencies, tool versions, seeds and state hashes; no reuse across changed upstream inputs. Validate clean vs resumed equivalence before claiming reusable checkpoints. Profile native flow stage timing and support early termination only with documented hard failures. Local final flow is not official signoff.
7. Ranking: correctness and immutable constraints are hard gates; incomplete evidence is unknown, not pass. Compare feasible candidates on predicted worst corner slack, hold, electrical, overflow, area and cost with Pareto ranking; prefer robust margins, not moving violations. Fit stage-to-stage loss by path family/corner with empirical intervals and sample counts; separate same-path loss from global worst slack shift; use leave-one-run-out, avoid data leakage; small sample -> conservative unknown, no ML confidence theater. Promote only with independent review, report exact input hashes and remaining gates. Never automatically merge.
8. Evaluation: replay historical reports with future outcomes hidden from agents, benchmark ordinary Codex vs knowledge-only vs full controller on identical frozen inputs/tool versions/budgets and repeated seeds where possible. Hold out entire candidate families, not rows; historical cases already known to model may bias results. Track first proposed qualifying candidate, root cause accuracy against documented evidence, repeat rate, full runs, elapsed time, summed CPU, agent usage, intervention count, PPA, correctness. Report denominators, missing evidence and uncertainty. Synthetic fixture success is not real closure. Full benchmark requires local artifacts and native flow; do not synthesize fictional outcomes.

## Suggested tree
`pdforge/{README.md,WORKLOG.md,core/,adapters/,profiles/tripwire/,knowledge/,skills/,benchmarks/,tests/}`; keep generated state in ignored local scratch. CLI: `doctor`, `ingest`, `diagnose`, `compare`, `propose`, `campaign --dry-run`, `status`, `resume`, `benchmark`, `export`. Each must have help and JSON output; nonzero on invalid evidence. Expose minimal reviewed tools to agents, not entire database mutation permissions.

## Milestones and gates
M0 inventory and read-only archive replay; tests on supplied SE0 case, report missing artifacts. M1 parser and diagnostic suite; golden real reports if available, synthetic tests for malformed units, multi-corner, missing and changed paths. M2 version-pinned retrieval and skills; citations, verified command availability, no global changes. M3 durable controller and isolation; tests for duplicate, budget exhaustion, timeout, restart, concurrent reserve, path traversal, malicious proposal, baseline mutation and no-network policy. M4 native adapter and checkpoints; dry-run first, then small local smoke design if available and within budget; no TRIPWIRE full run without explicit authorization. M5 roles and campaign integration; mock agent tests then bounded real CLI diagnostic task if authenticated and authorized. M6 benchmark harness and retrospective evaluation, honest report. M7 deliver local usage and migration plan, no remote actions. Implement tests before expensive runs; stop blocked milestones but complete independent ones. A README alone does not satisfy any implementation milestone.

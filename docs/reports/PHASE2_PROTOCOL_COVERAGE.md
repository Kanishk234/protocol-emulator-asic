This is a coverage audit for the expanded Phase 2 goal: keep the three required protocols and preserve the other protocols that fit the existing general primitives and D-049 resource floor, while meeting the 20 ns timing target. It records current evidence gaps; it does not change the frozen architecture, broaden a checklist gate by itself, or tick a Phase 2 box.

## What the roadmap labels mean for hardware evidence

`docs/reports/PROTOCOL_SUPPORT.md` uses **Verified (model)** for programs exercised in `tripsim` against protocol reference models and, where available, sigrok. That is model evidence, not RTL or hardened-netlist evidence. **Expected (firmware)** means the primitives appear sufficient but a program/test is missing. **Needs primitive** identifies functionality requiring a general primitive addition. USB low speed is explicitly a feasibility study, not a support claim; 10BASE-T is marked not feasible.

D-049 measured the default compiled-program resource needs against a one-at-a-time floor of 2 lanes, 4 units with U0 full, 12 slots per lane, and 512 SRAM words. That is resource-budget evidence. It does not show that every program has run on RTL or a hardened netlist, nor that this floor routes at 20 ns.

## RTL verification progress

`test_internal/chip/test_l3.py` has 22 L3 cases: the twelve earlier cases plus PS/2 RX/TX, 1-Wire READ ROM, SWD, JTAG, SMBus, HDLC, LIN, CAN, and IR NEC repeat RX. The eight non-IR program groups (nine tests) pass locally on exact candidate `3393eea9a58c5cad9077cc360a8515d0e5ec8284` under Icarus and Verilator using its generated compact fabric map. IR repeat RX passes under both simulators after initializing its firmware scratch state, and tripsim's existing frame/repeat regression passes against the modified program. Local sigrok was skipped for these candidate-specific runs. Main-shape unit run 37048872125 passed the earlier twelve under both simulators with sigrok enabled. Expanded hardened-netlist workflow 37051434072 passed those twelve under Icarus 13 against GDS run 36799356107, which contains the same candidate RTL SHA. The updated 22-case hardened-netlist workflow 37101678657 is running against that same netlist; it can establish L3 functionality but not the missing physical signoff.

The first WS2812 chip-level run exposed a real host-throughput gap hidden by the model test's instantaneous input preloading. Byte-sized tokens at the nominal 1.26 µs pulse period could not keep the wire continuous over the host SPI link. The program now packs each LED's 24 GRB bits into two 12-bit length-in-token words and uses upper-tolerance timings; the reference waveform decoder then passes on RTL with actual host SPI traffic. This is a firmware/input-format adjustment and changes no hardening input.

The servo test sends a width update near the beginning of the first high pulse and checks that it changes the next pulse. It verifies 1.5 ms and 1.0 ms highs and exact 20 ms rising-edge periods. A separate timing probe found that a write started after the first falling edge completes 865 clocks later and misses the next pulse; tripsim with the same 865-clock delay produces the same one-frame-later update. This is host/program scheduling latency, not a waveform timing failure. The protocol program remains model-verified; this test adds implementation evidence for the timely-update case.

The remaining work for these added cases is sigrok-enabled CI and review of the running matching-netlist test. Later repeat the suite on the netlist from a fully passing hardening. Keep the tests in `test_internal/` so they can use the internal host setup; top-level `test/` remains gate-level safe.

The required UART/SPI-controller/I2C-controller cases and the original twelve-case suite have RTL evidence; the original suite also passed on an earlier hardened netlist for the same candidate. The new protocol tests add RTL evidence only, not hardened-netlist signoff. The 16% hardening timed out before final route and physical signoff. Phase 2 still needs a successful full hardening, nonnegative routed timing at 20 ns, precheck, gate-level tests, viewer output, and the count/budget decision.

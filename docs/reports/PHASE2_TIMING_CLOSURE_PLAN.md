## Ranked changes

1. **Remove serial selection from the late producer-load path.** In `trw_chan_port`, `src_load` passes through selected-source logic before tap/drop gating and the saturating counter. Prototype an explicit per-source select decode and balanced AND/OR reduction for the late load signal. A stronger version forms per-source drop terms using that source's valid/sequence/tag and early consumer state, then reduces them. This can replace mux→tag/filter→late gating with parallel qualification. Keep invalid-source behavior, write priority, F4 overwrite accounting and F5 re-pointing exact. Cost: possibly duplicated qualification gates and more source fanout. Compare netlist depth and late-input delay, then routed results; RTL appearance alone proves nothing.

2. **Shorten the timer arithmetic feeding producer events.** The prior failing route had115/119reported failing path pairs starting atU0PERIOD word4bit10 and ending mostly in DROPPED state. Trace the newest route before selecting the exact timer. Look for cascaded add/subtract/mux stages that can be combined into one arithmetic operation, or implement short carry groups with parallel carries for existing timer widths. Preserve fractional timing, wrap, reload and live reconfiguration behavior. Prefer a combinational rewrite with no additional state. Cost: carry lookahead/select duplication and placement area. Any registered lookahead must handle every reload/configuration change and requires separate behavioral justification; it is not a free pipeline cut.

3. **Finish the counter endpoint experiment.** Existing `drop_counter.patch` computes toggle conditions from registered counter state and leaves late drop gating at each bit. Module equivalence and million-clock L2 pass;37489333139 passes estimated setup/hold but slow slew increases8→9. It needs routed measurement, not another estimate. This targets the last part of the critical cone; it may combine with source-path shortening only after each change has independent evidence.

4. **Improve critical-cone locality rather than global density alone.** Use routed path reports to group the U0event/load producer, relevant fabric consumer and dropped-counter cluster, and split long shared controls near their sinks. The SRAM buffer experiment already improved extracted setup by0.346752ns and cleared negative hold slack. Measure cell delay, net delay, clock skew and routed branch lengths separately before choosing placement/buffering. Cost: displaced neighboring cells, routing pressure and potentially hold repair. Do not broadly buffer unrelated nets or claim source/sink cell distance is routed length.

5. **Optimize for margin before DRT.** Zero estimated setup WS has repeatedly become negative after extraction. Test a positive resizer setup margin, initially around1.5–2ns based on observed routed loss, using the existing screen helper and unchanged signoff SDC. This is an optimization target, not a timing exception or a relaxed clock. Gate all-corner hold and electrical checks, routing overflow and runtime; margin can grow buffers and worsen congestion. Actual path slack, not clamped WNS, must establish headroom. Flow/config promotion needs an explicit documented decision under current repository restrictions; do not modify template jobs.

6. **Scale the winning cone changes to frozen full counts early.** Once an isolated change survives extraction, screen3lanes/6units with the same features/slots/SRAM to expose extra fanout and congestion. Reduce replicated combinational decode/read mux/arithmetic where general and equivalent; do not remove protocols or narrow documented precision. Shared decode saves area but may create long high-fanout nets, so share locally or replicate small controls deliberately. If full counts cannot fit, record that blocker and obtain a separate resource/spec decision rather than declaring the floor design complete.

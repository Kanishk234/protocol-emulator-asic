# Phase summaries

Plain-language accounts of what happened in each phase, written for someone who wasn't there: what we did, why it mattered, what we found, and what's left.

| Phase | Summary | Status |
|---|---|---|
| 0: setup | [PHASE0.md](PHASE0.md) | Complete |
| 1: spec, model and risks | [PHASE1.md](PHASE1.md) | In progress |

**How these relate to the other docs:**
- `docs/design/phases/` holds the **plans**: tasks and exit checklists, written before each phase starts.
- These summaries are the **outcome**: the story, in plain words, with pointers to the evidence.
- `docs/WORKLOG.md` is the detailed session-by-session log. `docs/DECISIONS.md` and `docs/BUGS.md` hold every decision and bug. `docs/reports/` holds the measured numbers.

A summary is written (or finished) when its phase ends. Technical detail stays in the linked documents; a summary should make sense on its own.
